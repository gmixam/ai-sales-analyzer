## 1. Какие шрифты реально встроены в PDF

Генератор просит `Arial`, но после конвертации через LibreOffice в PDF фактически встроены такие шрифты:

| Шрифт в PDF | Почему появляется |
| --- | --- |
| `LiberationSans` | Обычный текст, подмена Arial |
| `LiberationSans-Bold` | Жирный текст, заголовки, акценты в таблицах |
| `LiberationSans-Italic` | Цитаты, фрагменты, курсивные примечания |
| `DejaVuSerif-Bold` | Резервный шрифт для отдельных символов / emoji-подобных знаков |

Риск: визуально финальный PDF фактически не Arial, а Liberation Sans. Для кириллицы это нормально, но плотный текст 8-10pt читается тяжело.

## 2. Текущая шкала размеров PDF/DOCX

В `docx` значение `TextRun.size` хранится в half-points. Поэтому `22` означает примерно `11pt`.

| Токен | DOCX size | Примерно pt | Где используется сейчас | Комментарий по читаемости |
| --- | ---: | ---: | --- | --- |
| `SZ.h1` | 38 | 19pt | Имя менеджера; крупные числа итогов | Читается хорошо |
| `SZ.h2` | 26 | 13pt | Заголовок отчета; заголовки разделов | Читается, но не выглядит крупным |
| `SZ.accent` | 24 | 12pt | Определен, но сейчас почти не используется | Можно использовать для среднего акцента |
| `SZ.body` | 22 | 11pt | Основной текст, ключевые строки, обычные ячейки | На границе комфорта для плотного PDF |
| `SZ.cell` | 20 | 10pt | Компактные ячейки, фрагменты, диалог, подписи | Главная зона проблемы |
| `SZ.meta` | 18 | 9pt | Примечания, заголовки таблиц, scope notes | Слишком мелко для рабочего чтения |
| `SZ.caption` | 16 | 8pt | Подписи итогов, footer | Нормально только для настоящих подпунктов/футера |

Источник: `scripts/generate_docx_report.js`, константа `SZ`.

## 7. Главные проблемы читаемости

1. Слишком много смыслового текста выводится в 9-10pt:
   - заголовки таблиц;
   - диалоговые фрагменты;
   - фрагменты в разборе звонка;
   - интерпретация в "Голосе клиента";
   - контекст/рекомендация в "Кого взять в работу";
   - тип/контекст в списке всех звонков.

2. Серый текст одновременно мелкий и низкоконтрастный:
   - `#888888` при 8-10pt тяжело читать в PDF.

3. Плотные таблицы не имеют явного контроля line-height:
   - DOCX использует компактные параграфы и небольшие поля ячеек.

4. Иерархия разделов сжата:
   - `h2` всего 13pt, поэтому плашки разделов визуально близки к обычному акцентному тексту.

5. Есть две системы стилей:
   - PDF/DOCX стили в `scripts/generate_docx_report.js`;
   - HTML-preview стили в `layout.css`;
   - изменение только CSS не улучшит доставляемый PDF.

| `COLORS.gray` | `#888888` | `#5F6368` или темнее |

Самая безопасная первая правка:

- Увеличить `cell`, `meta` и заголовки таблиц.
- Затемнить `COLORS.gray`.
- После каждой правки пересобирать тот же PDF Толегена и следить за количеством страниц.
